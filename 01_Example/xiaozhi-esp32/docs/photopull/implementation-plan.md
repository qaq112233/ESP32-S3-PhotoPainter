# ESP32-S3 PhotoPainter：HTTPS 清单同步与 SD 多照片轮播修订方案

## 一、目标与已确认的行为

第一版采用 **HTTPS 定时拉取、SD 内容寻址存储、本地清单轮播**，不引入 MQTT，不调整分区。

已确认的产品行为：

- **首次自动，之后记忆**：没有保存过业务模式时，若 SD 配置有效且启用同步，默认进入 Network；否则进入 Basic。以后尊重用户保存的模式，SD 配置不覆盖主动选择的 Basic。
- **同步与轮播分离**：`enabled=false` 只停止远程同步；Network 模式下仍按最后提交的本地清单轮播，不删除缓存。
- **保留 STA/AP Web 上传**：不新增登录，接受可信局域网内其他设备也能上传的风险；不扩大 Web 可读取的 SD 文件范围。
- **离线优先**：本地照片库恢复、轮播和维护服务不等待服务器、TLS 或 SNTP 成功。
- **Network 常驻**：ESP32 与 Wi-Fi 保持工作，关闭该模式原有自动深睡及长按深睡入口；Basic 原有低功耗行为保留。
- **Lite 默认构建**：默认不编译小智功能；保留 Basic、Network、按键、电池状态显示和无音频模式选择。

## 二、配置与清单协议

### 2.1 SD 配置

固定路径：`/sdcard/photopull.json`。配置只在启动时读取，修改后重启生效，第一版不做热加载。

```json
{
  "schema": 1,
  "enabled": true,
  "wifi": {
    "ssid": "MyWiFi",
    "password": "password"
  },
  "server": {
    "base_url": "https://photos.example.com",
    "manifest_path": "/photopainter/manifest.json",
    "bearer_token": "",
    "ca_file": "/sdcard/photopull-ca.pem"
  },
  "poll_interval_sec": 60,
  "default_display_interval_sec": 300
}
```

配置规则：

- SD 中非空 SSID 优先；未提供时读取原有 NVS 凭据。空密码允许表示开放网络。
- SD 凭据仅用于本次运行，不覆盖原有 NVS Wi-Fi 凭据。SD 凭据连接失败进入维护模式，不静默改用另一套 NVS 网络。
- 配置缺失、解析失败或服务器字段非法时，禁止远程同步，但不删除或停用已经恢复的本地图库；仍可使用 NVS Wi-Fi 和维护模式。
- `enabled=false` 时允许省略 `server`；已有图库继续使用提交时保存的轮播间隔。
- 轮询间隔默认 60 秒，显示间隔默认 300 秒；二者配置范围均为 60～86400 秒。
- 配置最大 8 KiB；URL 最大 512 字节，令牌最大 2048 字节，CA 文件最大 16 KiB。SSID、密码按 Wi-Fi 接口容量检查，不允许截断后继续连接。
- 密码、令牌、完整配置和 NVS 凭据不得输出到日志；同时清理旧代码中的密码日志。

### 2.2 服务端清单

沿用原有字段：

| 字段 | 约定 |
|---|---|
| `schema` | 固定为 `1` |
| `generation` | 1～64 字节的照片库标识，重建图库时更换 |
| `revision` | 非负 32 位整数，同一 generation 内递增 |
| `display_interval_sec` | 可省略；省略时使用 SD 配置默认值，范围 60～86400 秒 |
| `photos` | 有序数组，最多 50 项；空数组表示有效的空图库 |
| 每张照片 | 必须包含 `id`、`path`、`size`、`sha256`、`width`、`height`、`format` |

具体约束：

- **清单上限由 16 KiB 调整为 32 KiB**；`id` 最大 64 字节、`path` 最大 256 字节、ETag 最大 256 字节。
- `id` 在清单内唯一；不同 ID 可以引用相同 SHA，存储时只保留一份文件。
- `sha256` 必须为 64 位十六进制，设备统一转换为小写。
- `path` 必须以单个 `/` 开始，仅允许普通 ASCII 路径字符；拒绝路径穿越、百分号编码、反斜杠、查询串、片段和控制字符。不得从远程路径生成本地文件名。
- 只允许 HTTPS 同源请求，第一版禁止 HTTP 重定向。Bearer Token 只发送给配置的来源。
- 公共证书使用固件内置的 ESP-IDF 证书 bundle；指定私有 CA 后，其缺失或解析失败必须停止同步，不得降级校验。
- 优先使用域名；IP 地址连接必须通过对应 IP SAN 校验，不能关闭主机身份检查。

### 2.3 图片格式与版本判定

服务器图片采用规范化 BMP：

- `format` 固定为 `bmp24-6color`。
- 14 字节文件头、40 字节信息头、像素偏移 54。
- `planes=1`、24 位、无压缩、正高度，像素按 BMP 的 BGR、由下到上排列。
- 尺寸仅接受 `800×480` 或 `480×800`，文件总长为 **1,152,054 字节**；2 MiB 作为接收硬上限，不能替代精确长度检查。
- 像素只允许 RGB：黑 `000000`、白 `FFFFFF`、红 `FF0000`、绿 `00FF00`、蓝 `0000FF`、黄 `FFFF00`。
- Web 上传的预处理 BMP 使用同一校验器；Basic 的普通 JPG/PNG/BMP 解码功能继续保留，并补齐公共解析路径的边界检查。

版本判定规则：

- 同一 generation、较小 revision：拒绝回退。
- 同一 generation、相同 revision：规范化后的清单内容必须相同，允许 JSON 空白变化。
- 更大 revision，或新的 generation：允许进入更新流程。
- 来源改变后不沿用旧来源的 ETag 或 revision 比较，但保留旧图库播放，直到新来源成功提交。
- **ETag 只随成功提交的本地快照持久化。**候选清单下载失败，不得覆盖已提交 ETag。
- 本地文件缺失或损坏时停止发送条件请求，重新取得清单并修复；不能把 304 当作本地完整性证明。

## 三、实现设计

### 3.1 启动、联网与维护

启动顺序调整为：

**基础硬件与 NVS 初始化 → 挂载 SD、读取配置 → 确定业务模式 → 恢复本地图库并启动播放 → 建立 STA/AP 和 Web 服务 → 校时 → 首次远程同步。**

- Network 模式下，STA 连接等待上限为 20 秒；失败后开放 AP 维护，同时按退避策略后台重试 STA。
- STA 恢复后，无 AP 客户端时关闭自动回退的热点；仍有客户端时保留至其断开。用户按键主动进入的维护热点在本次运行中保持开放。
- 服务器、TLS、认证或 SNTP 失败只影响远程同步，不触发 STA/AP 来回切换。
- 冷启动首次 HTTPS 前，执行一次最多等待 10 秒的 SNTP 校时；失败进入同步退避。成功后每 6 小时后台校时，轮播始终使用单调时钟。
- SD 挂载失败不格式化、不清屏，进入 AP 维护；提供固件内置的最小状态页，提示插卡后重启，上传返回明确的存储不可用错误。
- 保留按键进入维护模式、电池状态显示和模式选择；切换业务模式前停止新任务，完成或超时退出当前刷新、关闭文件后再重启。

### 3.2 服务边界与调度

采用 **一个状态/存储/显示管理任务，加一个 HTTPS I/O 任务**，不再让单个任务承担可能阻塞的 DNS、TLS 和所有业务操作。

- 管理任务独占已提交清单、候选清单、轮播游标、SD 文件变更和 Network 模式显示入口。
- HTTPS 任务只执行网络操作，通过有界的 4 KiB 数据块队列交付数据；不直接写 SD、不修改清单、不调用屏幕。
- 原 Web 服务任务继续处理 HTTP 收发，文件访问通过统一存储入口执行；上传数据使用有界缓冲与背压，不整图驻留内存。
- 网络事件和定时器回调只投递事件；同类轮询、轮播事件合并，最多保留一个待处理事件。
- 刷屏期间停止发放新的图片读取配额、暂停其他 SD 操作；已在途的数据最多进入有界缓冲，不能并发写盘。刷屏结束后继续，连接失效则重新下载当前文件。
- 不在等待网络时持有 SD 或显示锁。公共显示驱动仍保留互斥保护，初始化、图片刷新、电池状态和清屏都必须经过该入口。

默认网络预算：

- 连接阶段超时 10 秒，单次读取超时 5 秒。
- 清单请求总时限 30 秒，单图请求总时限 300 秒。
- 一轮同步最多运行 30 分钟；超时保留已验证的新文件，下轮继续复用。
- 失败以配置的轮询间隔为基数指数退避，上限为 `max(poll_interval_sec, 3600)`，附加 ±10% 抖动；成功后恢复正常间隔。
- 显示失败采用独立退避，不因轮播截止时间已经过期而形成重试忙循环。

### 3.3 下载、双副本提交与恢复

受管理目录固定为：`/sdcard/07_server_photos/`。

目录内保留两个本地快照槽、SHA 命名的图片及服务专用临时文件。快照记录本地格式版本、递增 `commit_seq`、来源标识、ETag、规范化清单和整体校验和。

同步流程：

1. 拉取并完整校验候选清单，计算缺失内容及所需空间；空间不足时直接失败，不提前删除当前图库。
2. 已有文件必须通过长度、摘要和格式校验后才能复用；本次运行中已验证且未变动的文件可复用验证结果。
3. 新文件流式写入 `.part`，检查接收长度、SHA、BMP 结构和六色像素；完整同步并关闭后再发布为 SHA 文件。
4. 写入较旧或无效的快照槽；检查写入、刷新缓冲、文件同步和关闭结果，再重新读取验证。
5. **第一个新快照完整落盘即为逻辑提交点**：更新内存中的当前图库、ETag 和显示调度。
6. 将另一槽镜像为同一个已提交版本并重新验证。镜像失败时继续播放当前完整图库，暂停后续新提交和清理，优先修复镜像。
7. **两个槽都完整指向同一版本后**，才删除该版本未引用的受管理图片及残留临时文件。

恢复规则：

- 按本地 `commit_seq` 选择最新且文件完整的有效快照，不跨 generation 比 revision。
- 一新一旧时先恢复新快照，再补齐镜像，最后清理。
- 快照校验正确但图片不完整时，可将其作为修复依据；离线期间仅播放校验成功的条目，不把降级列表提交成新清单、不执行清理。
- 两份快照均不可用时保持现有屏幕内容，等待远程重新同步；禁止扫描目录自行构造权威轮播顺序。
- 无效配置、网络错误、SD 错误都不能被解释为空清单。
- 清理只处理服务保留命名空间内的文件，保留目录内无法识别的文件，不递归删除用户目录。

掉电恢复承诺限定为：**文件系统仍可挂载、已同步的数据未发生介质级损坏时，恢复至少一套完整版本。**双副本不承诺解决任意 SD 控制器或介质损坏。

### 3.4 轮播、手工显示与屏幕电源

轮播规则：

- 启动恢复有效图库后，从第一张开始；不持久化轮播游标。
- 首次得到非空图库立即显示第一张。
- 普通更新与重排保留当前服务器照片；以 ID 维持游标，以 SHA 判断内容替换。
- 当前服务器照片被替换时显示替换内容；被删除时选择新清单第一张。
- 空清单提交后尽快清白屏，并在双副本镜像完成后清理图片；重复收到同一空状态不重复刷新。
- 显示间隔从上一次成功刷新并完成断电后计算。仅一张不变照片时不周期性重刷；切换到相同 SHA 也跳过物理刷新。

Web 与电池显示：

- 保留原 `/dataUP` 的“模式字节＋BMP”请求格式及成功时 HTTP 200 行为；模式字节不得再触发常驻 Network 深睡。
- 上传先进入独立临时文件，完整校验并落盘后才接受显示请求；失败不能破坏上一张有效上传图片。
- 同时最多一个上传及一个待显示手工请求，超出容量返回忙错误，不静默覆盖已接受请求。
- 上传成功表示文件已保存、显示请求已接受；不能宣称屏幕已经刷新完成。
- 手工照片和电池状态显示结束后重新计算间隔；下个周期恢复服务器游标的下一张，游标失效则从第一张开始。
- 普通清单更新不打断手工显示；新提交的空清单优先清白屏。后续手工上传仍可显示，下个周期恢复空图库的白屏状态。

驱动改造：

- 去掉散落在任务启动处的 EPD 上电初始化，改为准备刷新时按需初始化。
- 初始化和上电等待分别最多 10 秒，刷新等待最多 120 秒，断电等待最多 10 秒；所有阶段返回错误。
- SPI 和文件错误不得通过 `assert` 直接终止正常清理流程。
- 每次显示事务仅在图像准备完成后上电；正常刷新结束执行并确认 `POWER_OFF`。
- 异常路径尝试有界断电并标记驱动需重新初始化；无法确认断电时报告故障，不能记录刷新成功。
- 显示失败按 30、60、300 秒退避，之后维持 300 秒重试；任务仍须处理维护及网络状态，不进入无限 BUSY 等待。

### 3.5 Lite 构建与兼容迁移

- 新增默认关闭的 `CONFIG_PHOTOPAINTER_ENABLE_XIAOZHI`；关闭时从源文件、组件依赖及资源生成三层排除小智、音频、语音识别、MQTT、MCP、AI/天气和专用 UI。
- 保留开关开启后的 Full 构建，不采用“删除实现但保留无效开关”的方式。
- Lite 模式选择只保留 Basic、Network，以 LED 闪烁反馈；不初始化 codec，不播放模式提示音。
- Lite 启动遇到旧模式 3 时，一次性迁移并保存为 Network；Full 不执行该迁移。
- Basic 的定时配置解析独立于 AI，保留原文件格式、`timer` 字段和默认行为，不再要求 AI 地址或密钥存在。
- 按实际引用清理 `WHOLE_ARCHIVE`、LVGL、摄像头、触摸、音频和字体资源；保留 EPD 状态显示确实使用的字体，以及 Basic 需要的图片解码。
- 不调整分区，不新增 OTA 下载功能；保留最小 OTA 启动确认逻辑，使其不再依赖小智 Application。确认条件为关键初始化和业务或维护任务就绪，不依赖联网、校时成功。

## 四、测试与验收

| 测试组 | 必须覆盖的场景 |
|---|---|
| 模式与配置 | 首次自动选择、已保存 Basic 不被覆盖、旧模式 3 迁移、`enabled=false` 继续缓存轮播、配置缺失或损坏 |
| 网络与安全 | SD/NVS 凭据优先级、STA 失败转维护及恢复、TLS/CA/校时失败、重定向拒绝、路径穿越、日志无密码令牌 |
| 清单与缓存 | 首次 50 张、增删改排序、重复 ID、generation 切换、revision 回退、同版不同内容、空清单 |
| ETag 与修复 | 新 ETag 后下载失败、本地损坏时收到 304、来源切换、已下载内容跨失败轮次复用 |
| 存储与掉电 | 下载中、两个快照槽写入及同步前后、镜像失败、清理过程中断电；SD 满、短写、拔卡、挂载失败 |
| 调度与显示 | 慢网跨越轮播周期、连续上传、上传与电池显示交错、BUSY 卡住、SPI 失败、单图与空图库不重复刷新 |
| 构建与常驻 | Lite/Full 构建、Basic/AP/STA 上传回归、OTA 启动确认、24 小时运行与资源统计 |

验收门槛：

- Lite 应用镜像 **不超过 3,604,480 字节**，在现有 OTA 槽中保留至少 512 KiB。
- 24 小时常驻无崩溃、栈溢出、持续堆下降和任务队列增长；记录内部堆、PSRAM、最大连续可用块及栈高水位。
- 抽样断电测试必须验证重启后的完整照片集合，而不只是清单可解析。
- 验证屏幕实际电源行为；软件记录发送 `POWER_OFF` 不能替代硬件确认。
- 正常维护操作不能被整批图库下载阻塞；无正在进行的刷新时，手工显示请求应在当前有界操作完成后优先处理。
- 软件测试、构建结果与未完成的硬件验收分开报告。

实施顺序固定为：

1. Lite 裁剪、模式迁移与无音频模式选择。
2. 公共图片校验、驱动超时和统一显示入口。
3. 离线图库、双副本提交、恢复与清理测试。
4. HTTPS、ETag、联网维护、Web 上传整合。
5. 全量回归、断电测试、尺寸及常驻验收。

## 五、假设与第一版边界

- 服务端继续使用现有 HTTPS 静态服务，负责生成规范化六色 BMP；不开发照片管理后台。
- 发布顺序为：上传不可变 SHA 图片 → 校验完整清单 → 原子替换清单 → 保留旧图片至少 24 小时后清理；清单内容变化必须产生不同 ETag。
- 设备更新必须同时容纳当前图库和新增内容。按规范化 BMP 计算，两套各 50 张约需 110 MiB，另留文件系统和手工上传余量。
- SD 明文配置及可信局域网无登录上传是已接受约束，不得因此放松 HTTPS 校验或开放配置文件下载。
- 第一版不包含 MQTT、下载断点续传、Web 配网 UI、多设备权限、服务器管理 UI、新增整机深睡、OTA 下载及分区迁移。
- 固件修改不包含自动烧录、擦除 Flash 或替换发布二进制；硬件操作需要单独授权。
